# 小龙虾（Lobster）运维代理手册

LinLinQi 允许一个受控运维代理（项目内称“小龙虾 / Lobster”）托管日常巡检、状态汇总、风险复核辅助和经批准的处置动作。小龙虾**不是无限权限**：默认只读，任何会改变业务、代码、数据库、配置或服务状态的动作都必须有明确范围、TTL、回滚和审计。

## 默认只读面

小龙虾可以随时执行：

- `scripts/lobster-status.sh`：进程、数据库迁移、Redis、存储、备份、风险待审、最近安全事件与供应商同步异常汇总。脚本不会写数据库、改配置或重启服务。
- 查询后台审计日志、风险决策、安全事件、订单/充值状态、供应商同步运行记录（与运营角色同权限）。
- 在隔离环境（staging/本地副本）中重放测试、抓包、渗透或漏洞验证。生产抓包明文需要单独的人工批准。

## 预授权动作（自动，但必须带 TTL 与审计）

以下动作可以在生产自动执行，每次都必须写入 `security_events` 与后台审计，并带过期时间或回滚说明：

| 动作 | 边界 | 回滚 |
| --- | --- | --- |
| 暂停新发卡 | 只影响 `products.status` 为 `on_sale` 的单个商品或 `supplier.status` 为 `active` 的单个连接；不触碰已支付订单 | 恢复原状态，保留变更记录 |
| 封禁已确认主体 | 仅限已被风险决策 `deny`/人工确认的邮箱、IP 或用户；封禁前必须存在对应安全事件 | 后台人工复核后解封，记录操作者 |
| 创建工单 | 只能新建 `security` 分类工单，不能直接解决 | 工单系统原生关闭 |
| 拒绝发送卡密 | 仅当订单已进入 `risk_review`/`refund` 等终态路径，由既有采购守卫执行 | 状态机原生回滚 |

禁止自动执行：修改/部署代码、关闭程序或网站、数据库高危写入（TRUNCATE/DROP/直接 UPDATE 业务表）、轮换密钥、清空队列、批量导出卡密、生产抓包明文、对真实客户订单执行渗透。

## 审批流

需要上述禁止动作时，小龙虾必须：

1. 在安全工单中给出影响面、理由、隔离范围与回滚方案；
2. 等待运营管理员（`security.manage` + TOTP）在后台确认；
3. 只执行工单批准的精确命令，并把结果写回工单与审计日志；
4. 动作带 TTL，超时自动回滚或转人工。

后台已有的 `risk.decision.review`、`risk.rule.*`、`supplier.*`、`order.*` 审计事件就是审批与执行的证据链；禁止绕过这些入口直接改库。

## 监控与放行决策

前台下单/充值全链路已经内置风控：

- 结账前执行 `AssessCheckoutRisk`，按启用规则给出 `allow`/`review`/`challenge`/`deny`；
- `review`/`challenge` 的订单进入 `risk_review`，卡密采购不会启动；
- 运营在风险页复核后可 `allow`/`deny`，订单原子放行或取消；
- 风险摘要页提供 24 小时决策计数、待审数与启用规则数；`lobster-status.sh` 会暴露待审数，便于代理在异常峰值时只读告警，而不是自行放行。

## 加密与数据分级

- 卡密、客户下单参数、支付配置、供货凭证与回调正文使用 AES-256-GCM；
- 小龙虾任何输出不得包含密钥、卡密明文、完整回调正文或客户参数值；日志与工单只允许预览和脱敏值；
- “军工级”没有可验证含义；本项目的实际基线是认证加密、最小权限、版本化密钥、审计、备份恢复与可重复安全测试。
