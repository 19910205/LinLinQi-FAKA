# 安全基线

## 密钥与敏感数据

- JWT、管理员 JWT、数据主密钥、Redis 密码和 OpenAPI Secret 必须独立生成。
- 生产配置检测到短密钥、默认值、演示值、相同 JWT 密钥或通配 CORS 时拒绝启动。
- 卡密、API Secret、支付配置、供货凭证和 TOTP Secret 使用 AES-256-GCM 加密。
- 根密钥只通过 Secret Manager/KMS 注入；不要写入镜像、仓库、日志或数据库。
- 单机 Compose 使用权限为 `0600` 的 `.env` 作为参考注入方式；这不能防范 Docker 管理员读取环境。生产编排支持 Secret Manager 时应由部署层注入同名变量并审计读取权限。
- 卡号/卡密列表只返回预览，导出和解密动作必须追加审计并限制权限。

## 认证与授权

- 用户 Access Token 15 分钟过期，Refresh Token 30 天并在每次刷新时旋转。
- 管理员使用独立签名域、12 小时令牌、数据库 RBAC 和 TOTP。
- 管理端生产账户必须启用 TOTP；恢复码只展示一次并只保存 SHA-256 哈希。
- 登录、下单、支付、OpenAPI 和工单端点通过 Redis 严格限流；Redis 故障时失败关闭。

## OpenAPI

- 签名原文包含时间戳、Nonce、方法、路径和请求体 SHA-256。
- 服务端校验时间窗，将 Nonce 保存到 Redis 6 分钟，并使用常量时间比较签名。
- `client_order_no` 必须全局唯一；调用方重试必须复用同一个外部订单号。

## Webhook 与出站请求

- Webhook 生产 URL 强制 HTTPS，拒绝用户信息和解析到私网、回环、链路本地或组播的目标。
- 每次投递携带时间戳和 HMAC 签名，响应体最多保留 64 KiB，数据库仅保存截断后的响应。
- 高敏部署应在网络层再配置出站代理/域名白名单，抵御 DNS rebinding 和供应链风险。

## TLS 与容器边界

- 生产 HTTP 端口默认只绑定 `127.0.0.1`，必须由受信任反向代理终止公网 TLS；不要把 `BIND_ADDRESS` 改为全网卡后直接提供明文服务。
- PostgreSQL/Redis 生产端口不发布，数据网络标记为内部网络。该隔离不等同于链路加密；需要东西向 TLS 的部署必须额外完成服务端和客户端证书配置。
- API 和前端运行时为非 root、只读根文件系统并移除 Linux capabilities；镜像构建上下文通过 `.dockerignore` 排除 `.env`、缓存、依赖目录和构建产物。
- 原生 macOS 媒体目录、配置、日志和备份应位于权限为 `0700` 的 `~/.linlinqi` 下，文件使用 `0600`。只有 `media/objects/sha256` 能通过经过路径校验的 API 路由公开；staging、quarantine、spool、环境文件和备份不得配置为 nginx alias。
- 本机保存卡密、凭证或客户媒体前必须启用 FileVault，并把恢复密钥存放在独立受控位置。FileVault 不替代应用层加密、异地备份或最小权限。

## 上线前测试

- SAST、依赖漏洞扫描、镜像扫描、密钥扫描和 SBOM。
- 登录与权限绕过、SSRF、Webhook 重放、支付回调伪造、金额篡改和并发超卖测试。
- 数据库备份恢复、Redis 丢失、支付回调延迟、上游超时和 Worker 重启演练。

## 供应链、媒体与自动化边界

- 供应商健康探针只允许只读能力；不会通过“测试连接”创建订单、租号或调用取消/退款。探针响应只含能力状态、数量、耗时和通用错误码，不返回上游正文或带密钥 URL。
- 远程分类图、商品封面、图库和描述图片必须经统一出站策略：HTTPS、公网地址、DNS/重定向复验、响应大小、MIME、像素和解码上限、内容 hash 去重、隔离失败对象。生产严禁 `TLS verify=false`。
- 订单建立不可变供应商绑定和持久库存 hold；采购成功/失败/超时用事务消费或释放。并发测试必须覆盖两个订单竞争同一上游最后一件库存。
- 不使用“军工级”之类无法证明的安全宣传。实际基线是现代认证加密、密钥版本/轮换、最小权限、数据分级、审计、备份恢复和可重复安全测试。
- “小龙虾”类运维代理默认只读观察；预授权动作限定为隔离单连接、暂停新发卡、封禁已确认主体和创建工单，且必须有 TTL、回滚和审计。自动改代码/部署/停站、数据库高危写入、抓包明文或渗透测试需要明确范围、隔离环境和人工批准，生产代理不得拥有无限权限。
