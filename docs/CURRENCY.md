# LinLinQi 多货币与汇率体系

LinLinQi 的金额字段统一保存为 `int64` 最小货币单位，并由 `currency_definitions.minor_unit` 决定小数位。JPY、KRW、VND 等零位货币不会除以 100；三位小数货币也不会被截断。汇率始终以 `numeric(38,18)` 对应的十进制字符串传输和保存，业务代码使用有理数计算，只在最终目标货币最小单位处舍入。

## 换算顺序

供应商商品先把上游成本换算为店铺币种，再计算加价：

```text
上游最小单位金额
  → 按上游 minor_unit 还原主单位
  → 乘不可变 FX 快照
  → 乘 (10000 + markup_basis_point) / 10000
  → 换成店铺 minor_unit
  → 最终一次舍入
```

例如上游成本为 USD 1.00、USD/CNY 为 `7.0267`、加价为 50%：

```text
100 USD cents × 7.0267 × 1.5 = 10.54005 CNY = 1054 CNY cents
```

系统不会先把成本舍入成人民币分再加价，因此不会积累双重舍入误差。订单项、采购单和同步记录会保存上游金额、上游币种、店铺币种、汇率与 FX 快照 ID，历史订单不会随以后汇率变化。

## 三档自动汇率

1. 实时档：并发轮询已启用的汇率源，默认最多 32 个、全局 20 秒、单源超时可配置、并发上限 5。系统保存每次观测，剔除超过 96 小时的旧值、未来时间和偏离中位数 5% 以上的异常值；至少两个来源达成共识才生成 `live` 快照。
2. 手工档：实时来源全部不可用时，选择当前有效的精确手工汇率；支持直接币对和反向币对，生成 `manual` 快照。
3. 缓存档：实时与手工均不可用时，复用七天内最后一个受信任的实时/手工快照，生成指向父快照的 `cached` 决策记录。超过可信窗口后拒绝自动改价，不猜测汇率。

初始迁移登记 Frankfurter 综合源、25 个官方参考数据源过滤器和 ExchangeRate-API 开放源，共 27 个可独立启停、排序和监测健康状态的来源配置。后台“币种与汇率”页面可管理来源、手工汇率、不可变快照和主动刷新。参考汇率是央行/官方日频参考数据，不等同于毫秒级外汇交易报价。

## 店铺币种切换

修改 `store_currency` 前必须先取得源币种到目标币种的有效 FX 快照。随后一个 PostgreSQL 事务原子换算本地商品、规格、阶梯价、促销规则、优惠券、会员消费门槛、经销商固定价和目标币种授信策略，再提交店铺设置。任一金额、约束或并发检查失败时整笔切换回滚。

供应商商品在切换后进入异步重新同步：成本始终从保存的上游原币种重新换算，不使用上一次店铺售价继续换算。供应商固定价会保留自身配置币种，并用独立 FX 快照换算到当前店铺币种。

以下事实账永不批量改币：历史订单、订单项、支付意图、退款、充值、钱包、礼品卡、推广佣金、提现、采购单和对账记录。它们按记录自身币种展示、退款和冲正，报表也只在同一币种内求和。切换完成后，新订单、新钱包入账和新的业务账统一使用新的店铺记账币种。

## 支付与前端

- 支付渠道显式声明 `supported_currencies` 和唯一 `settlement_currency`；前者说明连接器能力，后者是该渠道实际向客户收款的币种。创建支付、充值和退款时服务端再次校验。
- 用户可在前台从已启用币种中选择展示币种。该选择只影响商品报价和界面显示，不改变订单、钱包或佣金的后台记账币种；浏览器不保存汇率，也不自行换算金额。
- `GET /api/v1/products`、商品详情和 OpenAPI 商品目录接受 `currency`，返回目标币种整数金额以及 `fx.snapshot_id/source_currency/target_currency/rate/source_tier/expires_at`。同币种报价使用精确 `rate=1` 且不制造无意义快照。
- 购物车保存展示报价币种。切换币种时旧购物车不会静默改价，用户必须确认清空后重新选购；创建订单时服务端重新以当前 `store_currency` 锁定商品、会员、促销、优惠券和订单总额，绝不接受客户端提交的价格或汇率。
- 支付意图同时保存 `order_amount/order_currency` 与实际网关 `amount/currency`，跨币种时还保存不可变 `fx_snapshot_id`。例如订单记账为 USD、人民币渠道结算为 CNY，订单仍为 USD，支付请求和回调严格校验 CNY 金额。
- 退款由运营输入订单币种金额，服务端使用原支付链按比例换算为渠道币种；最后一笔退款吸收最小单位舍入差，订单账与网关账分别累计。
- 钱包与充值以后台店铺币种为准。充值同时保存实际支付 `amount/currency` 和钱包入账 `credit_amount/credit_currency`；前台展示币种不会创建另一套钱包事实账。
- 充值回调只有在渠道实收 `amount/currency` 与充值单渠道应收值逐字段一致时才能换算并写入钱包；已验签的错额、错币种或迟到收款仅保存最小化渠道事实与原文哈希，进入耐久原路退款状态，绝不按猜测汇率修正后入账。
- admin/user 通过公开币种注册表获得 `minor_unit`，金额展示使用 ISO 代码，不用硬编码 `¥` 或固定 `/100`。
- CSV 导出包含币种列，并按对应币种的小数位格式化。

## 供应商协议扩展

每个供应协议在 `api/internal/supply/protocol_*.go` 中单独实现和注册；共享文件只保留安全传输、标准化与注册表逻辑。新增协议时不得把协议路径、鉴权分支或字段映射塞回中央文件，并应同时补注册完整性测试、凭据字段定义、币种识别与能力声明。

## 供应商价格与库存审计快照

`ProductMapping` 与 `SupplierCategoryMapping` 的百分比统一保存为 basis points（5000 = 50%），固定金额保存为目标币种最小单位并带 `markup_currency`。同步记录同时保存 `last_upstream_price`、`last_upstream_currency`、`last_converted_cost`、`last_fx_snapshot_id` 和更新时间；因此运营可以还原某一订单当时的 `$1 → ¥10.54` 计算，而不会被今天的汇率或规则改写。

每个供应商商品行在订单创建事务里建立 `supplier_inventory_reservations`。预占量不属于收入或成本，不进入钱包/充值账；采购成功标记 `consumed`，支付过期、取消或供应商失败标记 `released` 并记录原因。公开库存是上游观察量减去活动订单 hold 的可执行库存，订单采购沿用相同的供应商/映射/币种快照。
